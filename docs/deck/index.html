Welcome. This is the AI Research Crew for Marketers. It is a team of specialist AI agents that does the desk research behind marketing decisions. It runs in the customer's own AWS account.

The key line: your team sets the strategy, the crew does the legwork. The marketing team stays at the center. It sets the goal, approves every plan, and makes every decision. The crew gathers facts, analyzes them and writes drafts for the team to review.

It is built on Amazon Bedrock AgentCore and comes as open-source AWS sample code. Each customer gets their own copy, set up for their brands, data and tools by their own team or a partner.

AI Research Crew for MarketersHuman in the loop

This slide answers the question "is this replacing my team?" The answer is no. Orange boxes show where the team acts. Dark boxes show where the crew drafts.

The team sets the goal. The planner drafts a plan. The team checks every task before saving: the instructions, which specialist does it, which tools it may use, and which AI model. A plan with errors can't be saved. With a fixed plan (static plan mode, which we recommend as the default), every run follows exactly the plan the team approved. That includes scheduled runs.

If a technical person asks: the tool list for each task is checked when the plan is saved and is given to the agent in its instructions. It is not yet enforced by the service while the task runs. This is a known AgentCore limit, D-24 in the Well-Architected review. Each agent can only reach the tools its own harness is allowed, and we keep that list as small as possible.

After the run, the team reads the report and can ask it questions. The report assistant answers only from the report and its sources. If the team asks for changes, the assistant suggests them one section at a time and shows exactly what would change. The team accepts each section or keeps the current text. Nothing changes until they save. Each save becomes a new version, and the original report is never overwritten. Only the workflow's owner or an admin can save.

Quick start · AWS-native boilerplate

One command to deploy. First run the same day.

1

Save your search API key in Secrets Manager

aws secretsmanager create-secret \
  --name marketing-workflow/tavily-api-key \
  --secret-string '<your-key>' \
  --region ap-southeast-2

News and social media keys are optional. Without them, reports say what they couldn’t cover.

2

Build and deploy with AWS CDK

npm install
npm run build
cd examples/marketing-workflow
npx cdk deploy -c modelId=<inference-profile-id> -c removalPolicy=destroy

Use removalPolicy=destroy for trials, so cleanup removes everything. Leave it out when you get closer to production.

3

Create a user (users can’t sign themselves up)

aws cognito-idp admin-create-user --user-pool-id <UserPoolId> \
  --username <name> --temporary-password '<TempPassw0rd!>'

Add the user to the admin group if they should manage agents and settings.

4

Open the web app and run your first goal

Open the WebAppUrl link from the deploy output, sign in, and type a goal. Check the draft plan, save it, and click Run now.

Watch each task’s status, time and token usage, then read the report.

Open source (MIT-0): improve it, white-label it, and own your customizations. No license fees and no attribution needed.

You need: Node.js 20 or later, AWS credentials, CDK bootstrapped, and access to Amazon Bedrock AgentCore and Bedrock models in your region (sample default: ap-southeast-2). Commands match the repository README.

Architecture

Serverless and AWS-native, in your own account

1

AgentCore Harness: the agents

Each agent is built from a config file and gets only the permissions it needs.

2

AgentCore Gateway: one door to tools

Agents use every tool through it (MCP). Keys stay in Secrets Manager, hidden from agents.

3

AWS Step Functions: runs any plan

One workflow runs every valid plan, with tasks side by side. By default, one failed task doesn’t stop the run. New plans need no new infrastructure.

4

DynamoDB and S3: records and results

Task status, time, AI usage and every output, encrypted with this workload’s own KMS key.

5

Cognito and CloudFront: the web app

Sign-in is required for every API call. EventBridge Scheduler runs repeat workflows.

AI Research Crew for MarketersArchitecture

Everything here is serverless and runs in the customer's own account.

One: each agent is an Amazon Bedrock AgentCore harness. It is set up from configuration and has its own execution role with only the permissions it needs. Two: agents reach tools through AgentCore Gateway, using MCP, the standard way for AI agents to call tools. Tool API keys stay in Secrets Manager and are read inside the tool layer, so agents never see them. Three: one general-purpose Step Functions workflow runs any plan. It runs tasks in the order their inputs allow, and runs tasks that don't depend on each other at the same time. By default it keeps going when a task fails: the failed task is recorded, tasks that needed it are skipped, and the report notes the gap. It ends with the report step. Because plans are data, a new research workflow needs no new infrastructure. Four: DynamoDB stores workflow, run and task records, including token usage. S3 stores every task output and report. Both are encrypted with a KMS key that belongs to this workload. Five: the React web app is served through CloudFront. Users sign in with Cognito, and every API call needs a Cognito token. EventBridge Scheduler runs the repeat workflows.

AI Research Crew for MarketersCustomization

This is how the crew is set up for each organization. There are three things you can change.

Agents: the portfolio expert holds the brand brief. Admins replace the starter brief in Settings. They can also change any agent's instructions or model without redeploying. The original settings can always be restored. Adding or removing an agent is one entry in a YAML file. The planner learns about a new agent from its description.

Tools: built in are web search through Tavily, news through NewsAPI, social media through EnsembleData, and currency rates from ECB reference rates, which need no key. There are also the AgentCore Browser and Code Interpreter. Customer systems such as CRM, sales or POS data, a product catalog, or brand guidelines are added as AgentCore Gateway targets. Each one is either a hosted MCP server or a small Lambda tool with its own secret. These are examples of what you can connect. They are not connectors that come in the box. Amazon Bedrock Knowledge Bases are not included in version 1.

Models: at deploy time you choose a default model, plus optional fast and deep models, from the customer's Bedrock inference profiles. The planner suggests a model for each task based on how hard the task is. The team can change it for each task before saving.

AI Research Crew for MarketersNext steps

How we roll this out to many customers: each customer gets their own deployment in their own AWS account. That is the only model in version 1, and customers are kept apart by the account boundary. It is not one shared service for many customers. Inside one deployment, everyone who signs in shares one workspace and can read all workflows and reports. Only owners or admins can change them.

Security basics: everyone signs in with Cognito, and every API call needs that sign-in. People can't sign themselves up, and an admin group manages agent and organization settings. A KMS key for this workload encrypts the data, stored outputs and logs. The running app can't create AWS infrastructure. The only thing it creates while running is a workflow's schedule.

A security reviewer will raise two known gaps. Both are on the Well-Architected list. First, the tool limits for each task are checked when a plan is saved, but they are not enforced while it runs. This is an AgentCore limit, D-24. Until it is fixed, each agent's harness is allowed as few tools as possible. Second, Cognito MFA is not set up. Turn it on before production, at least for the admin group.

Cost: an idle deployment costs about four dollars a month (about one dollar for the KMS key and three for the dashboard), plus cents for storage. The real cost is per run: Bedrock AI usage (tokens) plus any paid data services. The app tracks token usage for each task and each run. So updating a report costs one more run, not a new agency project. Remind customers that schedules keep running until someone turns them off.

Be exact about what is built in today. Built in: token usage of the worker agents for each task and each run in the app, and Bedrock spend per agent and per workload in Cost Explorer and the Cost and Usage Report (CUR), through cost allocation tags on each agent's IAM role. These tags need a one-time activation in the payer or management account. They don't cover past usage, and the data is about a day behind. Planner token usage and dollar amounts per step are not in the app yet. There is no spending cap per run, per brief or per user built in today. The only limits are plan size and each agent's limits on steps and tokens. We recommend adding AWS Budgets alerts on the workload tag, an alarm on the token usage rate, and a token budget per run in the Step Functions plan runner, which is on the roadmap. Because the code is MIT-0, builders can add spending limits per brief or per user, using the same token records.

Path: start with a discovery workshop to pick use cases and data sources. Then set up a pilot. Then customize the agents and tools. Then try the use cases, with the team reviewing every plan and report. Last, prepare for production using the Well-Architected list: a web firewall (WAF) and request limits, guardrails against prompt injection (harmful instructions hidden in web pages or data), an automated release pipeline (CI/CD), cost limits, and disaster recovery. This is sample code and it is not ready for production as-is. Close by agreeing on a date for the discovery workshop and the first two use cases.
